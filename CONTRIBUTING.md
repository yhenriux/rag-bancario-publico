# Como contribuir

Obrigado por ajudar a tornar o projeto mais claro e verificável.

## Você pode ajudar com a documentação

Se uma explicação estiver confusa, [abra uma sugestão](https://github.com/yhenriux/rag-bancario-publico/issues). Informe:

- Qual página você estava lendo.
- O que tentou entender ou fazer.
- Qual palavra ou passo causou dúvida.
- Como você explicaria isso, se tiver uma proposta.

Siga a [política de linguagem simples](docs/linguagem-simples.md).

## Você encontrou um problema no código?

Abra um relato com o comando usado, a mensagem de erro e a versão do Python. Use um exemplo fictício pequeno que permita repetir o problema.

Confira se o relato contém dados pessoais, senhas ou arquivos de avaliação restritos. Esses materiais precisam continuar fora do repositório público.

## Você quer alterar os arquivos?

Crie uma cópia de trabalho, faça a alteração e execute:

```bash
python -m unittest discover -s tests -v
python demo.py
```

Depois, envie uma proposta de alteração pelo GitHub, chamada *pull request*. Explique o problema, o que mudou e como você verificou a mudança.

## Mudanças no estudo

Mudanças nas hipóteses, perguntas, filtros, modelos ou critérios de avaliação precisam de revisão metodológica. Registre a justificativa e a nova versão antes da etapa final correspondente.

Os exemplos fictícios podem ajudar a testar o código. Eles devem continuar identificados como exemplos.

## Materiais dos bancos

Cada fonte conserva seus próprios direitos de uso. Inclua endereço e justificativa para uma sugestão de fonte. A coordenação revisa as condições de coleta e publicação.

A escolha da licença do código permanece uma decisão do responsável pelo projeto. A revisão dos direitos das fontes é feita separadamente.
